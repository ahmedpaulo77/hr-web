# HR Portal — واجهة نظام الموارد البشرية

واجهة عربية (RTL) كاملة لنظام موارد بشرية: بوابة موظف، لوحة مدير، ولوحة موارد بشرية (أدمن)،
مع موقع تعريفي عام، وضع ليلي/نهاري، وتصميم متجاوب.

> **ملاحظة مهمة:** هذه النسخة **واجهة أمامية فقط** وتعمل ببيانات تجريبية محفوظة في المتصفح
> (`localStorage`). لا توجد أي طبقة API — راجع قسم [الربط بالباك إند](#الربط-بالباك-إند).

## التشغيل

المتطلبات: **Node.js 22** و npm.

```bash
npm install
npm run dev
```

الرابط: `http://localhost:5173/`


## حسابات الدخول التجريبية

| الدور | البريد | كلمة المرور |
|---|---|---|
| موظف | `employee@hr.com` | `123456` |
| مدير مباشر | `manager@hr.com` | `123456` |
| موارد بشرية | `admin@hr.com` | `123456` |

> الدخول حالياً مكتوب داخل `src/pages/auth/LoginPage.tsx` (بدون API)، وأزرار "تجربة سريعة"
> في صفحة الدخول تستخدم نفس الحسابات. **قبل الإنتاج:** اربط الدخول بالباك إند واحذف الحسابات التجريبية.

## البيانات التجريبية ومسحها

كل البيانات محفوظة في `localStorage` تحت المفاتيح:

```
hr-auth  hr-employees  hr-requests  hr-operations  hr-dependents
hr-request-types  hr-organization-catalog  hr-settings  hr-theme
```

من **لوحة الموارد البشرية ← الإعدادات ← بيانات النظام**:

- **مسح البيانات التجريبية**: يحذف الطلبات وسجلات الحضور والتابعين، ويُبقي حسابات الدخول الثلاثة فقط.
- **استعادة البيانات التجريبية**: يرجع الموظفين والطلبات والحضور والتابعين وأنواع الطلبات لحالتها الأصلية.

لبداية نظيفة تماماً يمكن أيضاً حذف مفاتيح `localStorage` من أدوات المتصفح.

## الربط بالباك إند

كل قراءات/كتابات البيانات تتم داخل `src/store/*` فقط، والصفحات لا تتصل بالبيانات مباشرة.
هذا هو نقطة الاستبدال الوحيدة: استبدل جسم كل action بنداء API، وتبقى كل الشاشات كما هي.

| الملف | المسؤولية | نقاط API المقترحة |
|---|---|---|
| `store/authStore.ts` + `pages/auth/LoginPage.tsx` | الدخول والخروج والجلسة | `POST /auth/login` · `GET /auth/me` |
| `store/employeesStore.ts` | دليل الموظفين (إضافة/تعديل/حذف/تفعيل) | `GET/POST/PATCH/DELETE /employees` |
| `store/requestsStore.ts` | الطلبات والموافقات والرفض والإلغاء | `GET/POST /requests` · `POST /requests/:id/approve` |
| `store/requestTypesStore.ts` | أنواع الطلبات وحقولها ومسار الموافقة | `GET/POST /request-types` |
| `store/hrOperationsStore.ts` | الحضور، أرصدة الإجازات، مستندات الموظف | `GET /attendance` · `GET/POST /leave-balances` · `POST /documents` |
| `store/dependentsStore.ts` | التابعون | `GET/POST/DELETE /employees/:id/dependents` |
| `store/organizationStore.ts` | الأقسام والمسميات | `GET/POST /departments` · `/positions` |
| `store/settingsStore.ts` | بيانات الشركة والهوية وإعدادات الإشعارات | `GET/PATCH /settings` |

### ملاحظات للربط

- ملف `.env.example` يوضح متغيّر `VITE_API_BASE_URL` المقترح (غير مستخدم بعد).
- الإشعارات في الواجهة مشتقة من الطلبات الحالية، وإعدادات الإشعارات محفوظة لكن لا تُرسل بريداً — الإرسال مسؤولية الباك إند.
- رفع الشعار والمستندات حالياً يخزّن البيانات داخل المتصفح فقط (`data:` / أسماء ملفات)، ويحتاج رفعاً فعلياً عند الربط.
- تصدير التقارير CSV يتم في المتصفح من البيانات المحمّلة، ويمكن استبداله بتصدير من الخادم.

## النشر

- `vite.config.ts` يستخدم `base: './'`، والراوتر من نوع **HashRouter**، لذلك تعمل النسخة من أي مسار فرعي
  (مثل GitHub Pages) دون إعدادات إضافية.
- يوجد Workflow جاهز في `.github/workflows/deploy-pages.yml` ينشر `dist/` على GitHub Pages عند الدفع إلى `main`.
- لو استضفت على مسار فرعي بدون `/` في النهاية (مثل `example.com/hr-web`)، أضف الشرطة أو اضبط `base` على المسار الصريح.

## هيكل المشروع

```
src/
├── pages/        # صفحات الموقع العام + الموظف + المدير + الأدمن
├── layouts/      # تخطيطات (Landing / Auth / Employee / Manager / Admin)
├── components/   # عناصر مشتركة (TopBar, Sidebar, StatCard, ReasonDialog…)
├── store/        # Zustand stores — حدود البيانات مع الباك إند
├── data/         # بيانات تجريبية (موظفون، طلبات، أنواع طلبات)
├── lib/          # منطق مساعد (الموافقات، التنسيق، التقارير)
└── types/        # أنواع TypeScript
```

## قيود معروفة

- لا توجد طبقة API ولا مصادقة حقيقية (توكن `demo-token`)، والحسابات التجريبية ثابتة في الكود.
- البيانات محلية لكل متصفح، ولا تتزامن بين المستخدمين أو الأجهزة.
- إعدادات الإشعارات لا ترسل إشعارات فعلية.
- أرقام الصفحات قد تظهر عربية/لاتينية مختلطة حسب المتصفح.
